## Подготовка SourceCraft и GitVerse

```powershell
node scripts/prepare-hosting.mjs
```

Команда создаёт отдельные папки `netlify`, `sourcecraft`, `gitverse` и manifest с SHA-256. Она ничего не публикует. В SourceCraft добавляется `.sourcecraft/sites.yaml` с `site.ref: main`; корень репозитория будет корнем сайта. Для GitVerse включён `.nojekyll`. Предпочтительный отдельный публичный репозиторий на каждой площадке — `greenleaves`; его наличие и адрес нужно подтвердить после входа. Перед первой загрузкой проверить отсутствие чужого проекта с таким именем. Загружать содержимое пакета с сохранением папок `data/` и `studio/`.

В SourceCraft включить Sites для нового репозитория, в GitVerse выбрать публикуемую ветку и корень сайта в Pages. Не настраивать автоматическую синхронизацию с основной разработкой. Наличие HTTP 200 само по себе недостаточно: открыть главную страницу и `studio/?demo=1`, проверить каталог, расчёт и ссылки.

Официальные инструкции: [SourceCraft Sites](https://sourcecraft.dev/portal/docs/ru/sourcecraft/concepts/sites), [GitVerse Pages](https://gitverse.ru/docs/pages/quick-start/).

## Проверка и заморозка

```powershell
node scripts/verify-hosting.mjs https://greenleaves-lct2026.netlify.app/ docs/audit/netlify-check.json
```

Проверка выполняется без cookie или авторизации. Строгое побайтовое сравнение возвращает код 1 при любом несовпадении. Netlify меняет HTML: делает ссылки без `.html`, добавляет комментарий/бейдж хостинга. Поэтому `allMatched: false` требует просмотра отличий; это не следует скрывать или объявлять полным совпадением. На текущем релизе все 10 проверяемых URL доступны, все JS/CSS/SVG/JSON совпадают; HTML и переход к методике проверены в браузере. Подробности: [аудит](audit/2026-09-24-hosting.md).
