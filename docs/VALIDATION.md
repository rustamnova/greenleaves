- `node --test tests/*.test.mjs`: геометрические регрессии и CLI. Тесты покрывают площадь зданий/дорог/воды, замыкающее ребро, точные расстояния до сегментов, единицы, отсутствие/неоднозначность/самопересечение границы, неподдерживаемые объекты/OCS/bulge, неизвестные слои, межтиповое расстояние, все принятые точки, сценарии, миллиметры, лимиты и сохранение исходных сущностей.

- Независимый `ezdxf 1.4.4`: выходной DXF 2010 прочитан; 366 сущностей (6 исходных + 180 окружностей + 180 подписей), **0 ошибок, 0 автоматических исправлений**. Координаты и идентификаторы сверены с JSON отдельным скриптом.
- Реальный DXF из партнёрского архива: парсер выдаёт диагностику и блокирует расчёт на неподдерживаемой геометрии. Успеха реального проектирования не заявлено.

## Что эти проверки не доказывают

- Юридическую корректность значений отступов и пригодность пород.
- Работающий прогон полного набора 20 улиц.
- Сборку Docker, работу в МосТех.ОС или открытие в nanoCAD: эти проверки ещё не выполнены.
- Реальное снижение температуры, водопотребления, стоимости или сроков проектирования. Такие метрики пока не измерены.

## Воспроизведение

```bash
node --test tests/*.test.mjs
node scripts/cli.mjs --demo --output output/demo
python scripts/verify-dxf.py output/demo/planting-plan.dxf output/demo/report.json
```

Для последней команды нужен ezdxf. Проверки сохраняют временные локальные артефакты в `output/`, они не публикуются автоматически.

Дополнительная проверка публичной студии: файл examples/demo-input.dxf выбран через штатное окно; показаны 6 объектов, прежний экспорт заблокирован; после расчёта — 180 посадок. Файл обрабатывался локально браузером.
