## Получить разработку на свой компьютер

Требуется Node.js 20 или новее. Репозиторий: https://github.com/rustamnova/greenleaves. Право записи аккаунта `Pro-polyanskiy` подтверждено 29.09.2026.

С Git:

```sh
git clone https://github.com/rustamnova/greenleaves.git
cd greenleaves
node --test tests/*.test.mjs
node scripts/serve.mjs
```

Открыть http://127.0.0.1:4173/studio/?demo=1. Сервер работает, пока открыт терминал; остановка — Ctrl+C. Для браузерной студии установка npm-зависимостей не нужна.

Без Git: скачать ZIP проекта через **Code → Download ZIP** на странице репозитория или распаковать переданный командой архив `greenleaves-partner-2026-09-29.zip`. Открыть терминал в распакованной папке, где лежит `README.md`, и выполнить последние две команды выше. ZIP — снимок, новые изменения из GitHub в него автоматически не попадут. Для совместных правок предпочтителен клон Git.

## Открыть проект в Claude Code

Если под «Cloud Code» имеется в виду **Claude Code**, он может работать с этой локальной папкой. Участник использует свой аккаунт Claude и свою авторизацию GitHub. Установка и вход описаны в [официальной инструкции Claude Code](https://code.claude.com/docs/en/quickstart).

После установки, находясь в корне проекта:

```sh
claude
```

Первое сообщение агенту можно скопировать целиком:

```text
Ты подключаешься к проекту Greenleaves, задача №3 ЛЦТ 2026.
Сначала прочти AGENTS.md, README.md, docs/memory/CURRENT_STATE.md,
docs/memory/DECISIONS.md, docs/memory/SESSION_LOG.md,
docs/CAD_PREPARATION.md и docs/audit/2026-09-28-cad-pilot.md.
Затем изучи site/studio/engine.js, site/studio/app.js,
scripts/prepare-cad.py, scripts/cli.mjs и tests/.
Пока ничего не меняй и не публикуй. Объясни архитектуру,
что реализовано, что проверено и что мешает реальному пилоту.
Не считай демо проверкой 20 улиц. Соблюдай стоп-код из AGENTS.md.
Не загружай частные CAD и содержимое .private/ во внешние сервисы
без отдельного разрешения владельца.
```

В Git есть файлы состояния и история изменений кода. Личный чат Рустама с ассистентом, его настройки и авторизованные браузерные сессии в клон не передаются. Для продолжения разработки следует опираться на перечисленные документы и фактический код.

Если нужна именно среда разработки в браузере, GitHub поддерживает создание Codespace из репозитория: **Code → Codespaces → Create codespace**. Это отдельная облачная среда со своими лимитами/тарифами; для локального запуска она не требуется. [Официальная инструкция GitHub](https://docs.github.com/en/codespaces/developing-in-a-codespace/creating-a-codespace-for-a-repository). Среда Codespaces этим проектом ещё не проверена и не создана.

## Какие данные передаются отдельно

В Git/ZIP есть код, документация, тесты, публичный справочник и презентация. Реальные DWG/DXF, официальный большой датасет, пароли, переписка и локальные журналы `.private/` в публичный пакет не входят.

Для работы с реальным участком команде нужна отдельная закрытая папка с выбранными исходниками и аудитом, доступная конкретному аккаунту партнёра. Выдача доступа к такой папке не равна доступу ко всему Google Drive. В этой передаче права Google Drive не менялись и CAD-файлы никуда дополнительно не загружались.

Новый локальный каталог `Presentation/greenleaves-lct2026.pptx` у Рустама — побайтовая копия уже опубликованного `site/materials/greenleaves-lct2026.pptx` (проверено 29.09). Отдельная копия в Git не нужна.

## Текущее состояние и работа вдвоём

v0.3: общее JS-ядро студии и CLI, подготовка сложного CAD на Python, пространственный индекс, DXF/CSV/JSON, редактирование и проверки. На последнем прогоне — 21 тест JavaScript и 7 Python. Для Python нужен отдельный venv и зависимости из `requirements-cad.txt`; инструкция — в `docs/CAD_PREPARATION.md`.

Реальный фрагмент 3-й Парковой: распознано 22 307 геометрических фрагментов, но 2 490 REGION потеряли читаемое ACIS при конвертации. Расчёт реальных посадок заблокирован. Нужны полный проверенный CAD-экспорт, подтверждение слоёв и нормативная матрица. Презентация требует дополнения сведений и фотографий команды.

До стоп-кода правки согласовывать в отдельной рабочей ветке и через pull request; не перезаписывать изменения второго участника. После изменения геометрии запускать `node --test tests/*.test.mjs`; после изменения подготовщика — также `python -m unittest discover -s tests -p test_prepare_cad.py`. Публикация сайта только вручную после проверки.
