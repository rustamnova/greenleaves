# Проверка реального датасета — 28.09.2026

## Вывод

Предложение партнёра — провести реальный пилот: взять исходные чертежи одной улицы, получить предложения посадок и проверить выходной DXF. Данные для этого есть. Однако непосредственно загрузить ZIP или основную DWG-подоснову в текущую студию нельзя: v0.2 работает с одним подготовленным текстовым DXF.

Пробный запуск единственного DXF, найденного во внешнем архиве, завершился отказом из-за неподдерживаемой геометрии. В этом вспомогательном файле также нет автоматически распознаваемого контура проекта. План посадок не создан. Это проверка входа и диагностики, не успешный сквозной пилот.

## Источник и объём проверки

- Новая ссылка Fileditch при HEAD и GET с Range вернула HTTP 520. Содержимое по ней не получено; тождественность официальному архиву не установлена.
- Использован ранее переданный [официальный датасет организаторов](https://mostech-cloud.mos.ru/s/EpPFwWqDk3k82qp), файл «Пилотный проект 20 улиц.zip».
- Размер ZIP по Content-Range: **11 468 203 206 байт** (около 10,68 GiB, в интерфейсе 10,7 GB).
- Каталог ZIP прочитан через стандартные авторизованные запросы HTTP Range. Полный архив не скачивался.
- Найдены 4 562 записи; после исключения каталогов и служебных PaxHeader — 3 132 файла в 20 папках улиц.
- На внешнем уровне: **818 DWG, 1 DXF, 344 PDF, 51 вложенный архив** ZIP/7z/RAR. Вложенные архивы не раскрывались; это не утверждение, что внутри них отсутствуют дополнительные DXF. Содержимое всех DWG не анализировалось.
- Для 3-й Парковой извлечены 24 исходных/сопутствующих файла (CAD, отчёт передачи, шрифты; 141 786 561 байт), отдельно пояснительная записка PDF 430 103 байта. Итого 25 файлов, 142 216 664 байта. Для извлечения ZIP проверяет CRC; для файлов сохранены SHA-256. Шрифты и макросы не устанавливались/не исполнялись.
- Все CAD и подробные инвентари находятся в игнорируемой `.private/dataset-2026-09-28/` и не публикуются.

## Найденные компоненты пилота

В комплекте 3-й Парковой есть отдельная граница работ, исходный АПОТ, инженерные подосновы, дендроплан и внешняя ссылка «ГЕО+Границы работ». Отчёт передачи nanoCAD прямо указывает связь дендроплана с этой внешней ссылкой. Она извлечена с сохранением структуры папок. В отчёте также отмечены отсутствовавшие при упаковке растровая подложка и несколько шрифтов; полнота всех внешних связей в CAD ещё не подтверждена.

В архиве разделены «Исходные данные» и «Проектное решение». Пояснительная записка проектного решения содержит описание улицы и проектные ведомости озеленения (просмотрены страницы 1 и 5; текст извлечён из 9 страниц). Это материал для сопоставления с будущим результатом, не результат Greenleaves и не автоматически проверенная нормативная база.

## Следующий необходимый шаг

1. В локальной CAD-системе открыть исходную подоснову 3-й Парковой вместе с внешними ссылками, дендропланом и границей. Надёжный установленный DWG-конвертер при проверке PATH и списка установленных CAD-приложений не найден.
2. Подготовить один проверенный 2D DXF: сохранить единицы и координаты, включить существенные сети/здания/дороги/существующие насаждения, задать один действительный замкнутый контур. Сложные объекты преобразовать в поддерживаемую геометрию с проверкой сохранности смысла. Работать с отдельной копией исходников.
3. Учесть ограничения v0.2: 25 МБ DXF, 30 000 поддерживаемых объектов, до 2 000 вершин контура. При необходимости выбрать явно обозначенный небольшой пилотный фрагмент внутри реальной территории и включить все влияющие на него ограничения. Его нельзя выдавать за обработку всей улицы.
4. Повторить CLI/браузерный расчёт. При успехе проверить DXF независимым парсером, сохранность исходных объектов, расположение точек и журнал отказов. Отдельно сверить отступы с нормативной матрицей и экспертом.

Ожидаемый технический выход после подготовки: DXF с дополнительными слоями посадок, координаты/тип предложений и объяснения в JSON; CSV доступен в студии. Фактическое число допустимых посадок на реальной улице пока неизвестно.
